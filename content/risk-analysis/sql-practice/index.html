Q1 · Easy
Applications by Decision Status
Count the number of applications by decision status (Approved, Denied, Pending). Include the percentage of total applications for each status.
GROUP BY Aggregation ROUND Subquery
SQL 
SELECT
    decision,
    COUNT(*) AS app_count,
    ROUND(
        100.0 * COUNT(*)::NUMERIC / (SELECT COUNT(*) FROM APPLICATIONS), 
        2
    ) AS pct_of_total
FROM APPLICATIONS
GROUP BY decision
ORDER BY app_count DESC;
PostgreSQL Note: Used ::NUMERIC to explicitly cast COUNT(*) to numeric type for proper decimal division in ROUND(). In PostgreSQL, you must cast at least one operand to NUMERIC or DECIMAL to get decimal results.
Q2 · Easy
Top 5 Dealers by Approved Volume
Find the top 5 dealers by total approved loan amount. Include dealer name and region.
JOIN WHERE Filter LIMIT ORDER BY
SQL 
SELECT
    d.dealer_name,
    d.region,
    SUM(a.loan_amount) AS total_approved_amount
FROM APPLICATIONS a
JOIN DEALERS d ON a.dealer_id = d.dealer_id
WHERE a.decision = 'Approved'
GROUP BY d.dealer_name, d.region
ORDER BY total_approved_amount DESC
LIMIT 5;
Concepts: JOIN between APPLICATIONS and DEALERS. Filtering by decision status. TOP N pattern using LIMIT (PostgreSQL standard).
Q3 · Easy
Average FICO by Loan Amount Bucket
Group approved applications into loan amount buckets: 0-10k, 10k-20k, 20k-30k, 30k+. Calculate the average FICO score for each bucket.
CASE WHEN Bucketing AVG
SQL 
SELECT
    CASE
        WHEN loan_amount < 10000 THEN '0-10k'
        WHEN loan_amount < 20000 THEN '10k-20k'
        WHEN loan_amount < 30000 THEN '20k-30k'
        ELSE '30k+'
    END AS loan_bucket,
    ROUND(AVG(fico_score)::NUMERIC, 1) AS avg_fico,
    COUNT(*) AS app_count
FROM APPLICATIONS
WHERE decision = 'Approved'
GROUP BY loan_bucket
ORDER BY 
    CASE loan_bucket
        WHEN '0-10k' THEN 1
        WHEN '10k-20k' THEN 2
        WHEN '20k-30k' THEN 3
        ELSE 4
    END;
PostgreSQL Note: Used ::NUMERIC cast on AVG(fico_score) before ROUND(). This ensures proper decimal handling. The ORDER BY uses CASE to maintain logical bucket order.
Q4 · Medium
Delinquency Rate by Region
Calculate the 30+ DPD delinquency rate by dealer region. Use the most recent payment record for each account. Show region, total accounts, delinquent accounts (30+ DPD), and delinquency rate as a percentage.
Window Function ROW_NUMBER Multi-table JOIN Conditional COUNT
SQL 
WITH latest_payment AS (
    SELECT
        account_id,
        days_past_due,
        ROW_NUMBER() OVER (
            PARTITION BY account_id ORDER BY payment_date DESC
        ) AS rn
    FROM PAYMENTS
)
SELECT
    d.region,
    COUNT(DISTINCT ac.account_id) AS total_accounts,
    COUNT(DISTINCT CASE WHEN lp.days_past_due >= 30 
          THEN ac.account_id END) AS delinquent_accounts,
    ROUND(
        100.0 * COUNT(DISTINCT CASE WHEN lp.days_past_due >= 30 
              THEN ac.account_id END)::NUMERIC
        / NULLIF(COUNT(DISTINCT ac.account_id), 0), 
        2
    ) AS delinquency_rate
FROM ACCOUNTS ac
JOIN APPLICATIONS app ON ac.app_id = app.app_id
JOIN DEALERS d ON app.dealer_id = d.dealer_id
JOIN latest_payment lp ON ac.account_id = lp.account_id AND lp.rn = 1
GROUP BY d.region
ORDER BY delinquency_rate DESC;
PostgreSQL Note: Used ::NUMERIC cast in the division and NULLIF() to handle potential division by zero. ROW_NUMBER() window function identifies the most recent payment per account.
Q5 · Medium
Customers with Multiple Applications
Find customers who have submitted more than one application. Show customer name, number of applications, and the decision breakdown (Approved/Denied/Pending counts).
HAVING Conditional Aggregation JOIN
SQL 
SELECT
    c.customer_id,
    c.first_name || ' ' || c.last_name AS customer_name,
    COUNT(*) AS total_applications,
    COUNT(CASE WHEN a.decision = 'Approved' THEN 1 END) AS approved,
    COUNT(CASE WHEN a.decision = 'Denied' THEN 1 END) AS denied,
    COUNT(CASE WHEN a.decision = 'Pending' THEN 1 END) AS pending
FROM CUSTOMERS c
JOIN APPLICATIONS a ON c.customer_id = a.customer_id
GROUP BY c.customer_id, c.first_name, c.last_name
HAVING COUNT(*) > 1
ORDER BY total_applications DESC;
PostgreSQL Note: String concatenation uses || operator. Conditional aggregation using COUNT(CASE WHEN...) pattern is standard across SQL databases.
Q6 · Medium
Payment Collection Rate (Last 30 Days)
Calculate the collection rate over the past 30 days: (total payments received / total outstanding balance at the start of period) × 100. Assume outstanding balance is from the ACCOUNTS table.
Date Filtering Subquery Aggregation
SQL 
SELECT
    SUM(payment_amount) AS total_payments_received,
    (SELECT SUM(outstanding_balance) FROM ACCOUNTS) AS total_outstanding,
    ROUND(
        100.0 * SUM(payment_amount)::NUMERIC 
        / NULLIF((SELECT SUM(outstanding_balance) FROM ACCOUNTS), 0), 
        2
    ) AS collection_rate_pct
FROM PAYMENTS
WHERE payment_date >= CURRENT_DATE - INTERVAL '30 days';
PostgreSQL Note: Date arithmetic uses INTERVAL '30 days' syntax. CURRENT_DATE is a PostgreSQL function that returns the current date. Cast payment sum to NUMERIC and use NULLIF for safe division.
Q7 · Medium
Approval Rate by FICO Score Range
Calculate the approval rate for applications grouped by FICO score ranges: <600, 600-650, 651-700, 701-750, 751+. Show the count of applications, count of approvals, and approval rate percentage for each range.
CASE WHEN Bucketing Conditional Aggregation
SQL 
SELECT
    CASE
        WHEN fico_score < 600 THEN '<600'
        WHEN fico_score <= 650 THEN '600-650'
        WHEN fico_score <= 700 THEN '651-700'
        WHEN fico_score <= 750 THEN '701-750'
        ELSE '751+'
    END AS fico_range,
    COUNT(*) AS total_apps,
    COUNT(CASE WHEN decision = 'Approved' THEN 1 END) AS approved_count,
    ROUND(
        100.0 * COUNT(CASE WHEN decision = 'Approved' THEN 1 END)::NUMERIC
        / NULLIF(COUNT(*), 0), 
        2
    ) AS approval_rate
FROM APPLICATIONS
GROUP BY fico_range
ORDER BY
    CASE
        WHEN fico_range = '<600' THEN 1
        WHEN fico_range = '600-650' THEN 2
        WHEN fico_range = '651-700' THEN 3
        WHEN fico_range = '701-750' THEN 4
        ELSE 5
    END;
PostgreSQL Note: Used ::NUMERIC cast on the conditional count before division. NULLIF prevents division by zero errors.
Q8 · Hard
Top 3 Worst Dealers per Region (by Delinquency)
For each dealer, calculate the 30+ DPD delinquency rate (using most recent payment per account). Then rank dealers within each region by their delinquency rate (highest = rank 1). Show the top 3 worst dealers per region.
Multiple CTEs ROW_NUMBER RANK Multi-table JOIN
SQL 
WITH latest_payment AS (
    SELECT
        account_id, days_past_due,
        ROW_NUMBER() OVER (
            PARTITION BY account_id ORDER BY payment_date DESC
        ) AS rn
    FROM PAYMENTS
),
dealer_delinquency AS (
    SELECT
        d.region,
        d.dealer_name,
        COUNT(DISTINCT ac.account_id) AS total_accounts,
        COUNT(DISTINCT CASE WHEN lp.days_past_due >= 30
              THEN ac.account_id END) AS delinquent,
        ROUND(
            100.0 * COUNT(DISTINCT CASE WHEN lp.days_past_due >= 30
                  THEN ac.account_id END)::NUMERIC
            / NULLIF(COUNT(DISTINCT ac.account_id), 0), 2
        ) AS delinquency_rate
    FROM ACCOUNTS ac
    JOIN APPLICATIONS app ON ac.app_id = app.app_id
    JOIN DEALERS d ON app.dealer_id = d.dealer_id
    JOIN latest_payment lp ON ac.account_id = lp.account_id AND lp.rn = 1
    GROUP BY d.region, d.dealer_name
),
ranked AS (
    SELECT
        *,
        RANK() OVER (
            PARTITION BY region ORDER BY delinquency_rate DESC
        ) AS rank_in_region
    FROM dealer_delinquency
)
SELECT * FROM ranked
WHERE rank_in_region <= 3
ORDER BY region, rank_in_region;
PostgreSQL Note: Used ::NUMERIC cast on the conditional count and NULLIF for safe division. Multiple CTEs chain together to build the analysis step by step.
Q9 · Hard
Roll Rate — Delinquency Bucket Transitions
Build a roll rate matrix showing how accounts moved between delinquency buckets from December 2025 to January 2026. Buckets: Current (0 DPD), 1-29 DPD, 30-59 DPD, 60-89 DPD, 90+ DPD. Show the count of accounts for each transition (e.g., 30-59 → 60-89).
Self-Join Pattern CASE WHEN Bucketing Transition Matrix Real Credit Risk Task
SQL 
WITH monthly_status AS (
    SELECT
        account_id,
        TO_CHAR(payment_date, 'YYYY-MM') AS pay_month,
        MAX(days_past_due) AS max_dpd
    FROM PAYMENTS
    WHERE payment_date >= '2025-12-01'
      AND payment_date <= '2026-02-01'
    GROUP BY account_id, TO_CHAR(payment_date, 'YYYY-MM')
),
bucketed AS (
    SELECT
        account_id,
        pay_month,
        CASE
            WHEN max_dpd = 0  THEN 'Current'
            WHEN max_dpd <= 29 THEN '1-29 DPD'
            WHEN max_dpd <= 59 THEN '30-59 DPD'
            WHEN max_dpd <= 89 THEN '60-89 DPD'
            ELSE '90+ DPD'
        END AS dpd_bucket
    FROM monthly_status
)
SELECT
    b1.dpd_bucket AS dec_2025_bucket,
    b2.dpd_bucket AS jan_2026_bucket,
    COUNT(*) AS account_count
FROM bucketed b1
JOIN bucketed b2
    ON b1.account_id = b2.account_id
    AND b1.pay_month = '2025-12'
    AND b2.pay_month = '2026-01'
GROUP BY b1.dpd_bucket, b2.dpd_bucket
ORDER BY b1.dpd_bucket, b2.dpd_bucket;
PostgreSQL Note: Used TO_CHAR(payment_date, 'YYYY-MM') instead of strftime() for date formatting. TO_CHAR is PostgreSQL's standard date formatting function.
Q10 · Hard
Month-over-Month Origination Trend with Lag
Calculate monthly origination volume (count of approved applications and total loan amount). Add columns for the prior month's values and the month-over-month percentage change. Use window functions — no self-join.
LAG Window Function MoM Change Trend Monitoring
SQL 
WITH monthly AS (
    SELECT
        TO_CHAR(app_date, 'YYYY-MM') AS month,
        COUNT(*) AS approved_count,
        SUM(loan_amount) AS total_originated
    FROM APPLICATIONS
    WHERE decision = 'Approved'
    GROUP BY TO_CHAR(app_date, 'YYYY-MM')
)
SELECT
    month,
    approved_count,
    total_originated,
    LAG(approved_count, 1) OVER (ORDER BY month) AS prev_month_count,
    LAG(total_originated, 1) OVER (ORDER BY month) AS prev_month_amount,
    ROUND(
        100.0 * (approved_count - LAG(approved_count, 1) OVER (ORDER BY month))::NUMERIC
        / NULLIF(LAG(approved_count, 1) OVER (ORDER BY month), 0), 2
    ) AS count_mom_change_pct
FROM monthly
ORDER BY month;
PostgreSQL Note: Used TO_CHAR for date formatting and ::NUMERIC cast on the subtraction result before division. NULLIF handles division by zero for the first row where LAG returns NULL.
